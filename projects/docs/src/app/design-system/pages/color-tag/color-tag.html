One colour covers more than one client
There are six colours and no limit on records, so a colour always covers a group rather than one record. Scanning for it narrows a long list fast, which is the point of it, but two matching marks are not the same record. The mark is also aria-hidden, so a screen reader gets nothing from it at all. Pass label and the component prints the code beside the mark, so this is handled for you.
The six colours Six, and no seventh. The set is closed so that a colour keeps meaning the same thing everywhere it appears, and so the server can reject anything else. Each fill comes from the matching palette in styles.css at the -600 step, and those palettes invert between themes, so one class holds up on a light page and a dark one without a dark: variant.

There is no seventh value for "no colour". A record nobody has filed simply carries none, and the component draws nothing at all for it, so an unmarked row means unfiled rather than a colour of its own.
Card cut wraps an oct-card and takes its top-left corner out, so the color is part of the card's shape rather than laid on top of it. The card writes the client code in its own text.

Select Set colorTag on a SelectOption and the mark is drawn before its label, in the list and on the closed trigger. Multi-select shows its picks as badges and carries no mark. Open it: two options share the same amber mark, which is why the code stays in the label.

Table corner pins the mark to the first cell's top-left, which is the row's own corner, so a marked row reads like a marked card and costs the row no width at all. Reach it through TableColumn.template rather than render, whose string goes through [innerHTML] and loses the classes to sanitisation. Prop Type Default Description
color ColorTagColor null red, orange, yellow, green, blue, purple or none. `none` is a deliberate no-color, drawn as an unprinted tag rather than left blank, so it still reads as a choice.
label string null Text drawn beside the mark, truncating. Given one, the mark keeps its box even for an unfiled client, so a column of codes lines up on one left edge.
variant ColorTagVariant 'inline' All three draw the same right triangle and differ only in how it attaches. cut wraps the projected content and takes its top-left corner out. corner lifts the mark into the padding of the table cell it sits in. inline sets it in the caller's own text flow, for a select option with no corner to pin to.
Which variant goes where Settled for contract payroll, so the same client reads the same way on every surface. Pick from this rather than deciding per screen.
Cards use cut Job order detail, client detail, clientDept box, payroll run card. The corner is part of the card's own shape rather than something laid on top of it, which is what makes it read as the record's color and not a status.
Table rows use corner The mark sits in the first cell's padding, so it costs the column no width and an unfiled client needs no placeholder to keep the column aligned.
Select options use inline An option row has no corner to pin to, so the mark sits inline ahead of the label.
Known edges
